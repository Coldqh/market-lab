# MARKET / LAB — учебный движок 1.4

## Цель
Заменить одноразовые тесты на последовательную практику, которая проверяет вычисления и знания, отдельно от результата виртуальной торговли.

## Состояние на 1.4
**Существующие шесть тем остаются.** Новый модуль \`core/learning.mjs\` формирует шесть направлений вопросов с параметрическими вариантами:
1. Расчёт валового P&L длинной позиции;
2. Расчёт валового P&L короткой позиции;
3. Убыток от изменения цены относительно номинала (не залога);
4. Хедж производителя и потребителя;
5. Убыток относительно внесённого залога;
6. Номинал контракта по цене, множителю и количеству.

Это начальный набор навыков, а не финальный объём образовательной программы. Теория и справочник пока сохраняют прежнюю структуру.

## Как оцениваем
- Вопрос задаётся из deterministic seed и номера варианта, четыре перемешанных ответа, один верный.
- Один вопрос можно оценить **ровно один раз**. Повторный выбор уже оцененного варианта заблокирован.
- После ответа показываем объяснение и отдельную кнопку перехода к новому варианту.
- **Освоение** = две правильные попытки подряд на разных номерах вариантов. Ошибка сбрасывает серию, но не удаляет историю числа попыток.
- После освоения ставится условная дата повторения в шагах симуляции, \`nextReviewAt = currentStep + 96\`. Это не день реального календаря и не расписание уведомлений.
- Результат торговли (виртуальные деньги, P&L) намеренно не используется в формуле освоения.

## Практические действия
Пять целей регистрируются по фактам, происходящим в приложении:
- \`openLong\`: действительно открыта покупка фьючерса;
- \`advance\`: генератор рынка выдал новую свечу;
- \`close\`: пользователь вручную закрыл сделку;
- \`openShort\`: действительно открыта короткая позиция;
- \`scenario\`: сценарий применён к рынку.

Просто открытие вкладки/нажатие неактивной кнопки не добавляет практического прогресса. События с одинаковым идентификатором не учитываются дважды, используем реестр последних 250 ID, поскольку приложение работает в localStorage.

**Ограничение:** наличие действия не доказывает качество торгового решения. Проверка аргументации и риск-дисциплины должна появиться в следующих этапах.

## Миграция
- Текущий формат сохраняется под ключом \`marketlab-education-workstation-v7\`, исходные v4/v5/v6 не удаляются.
- Если поле \`learning\` отсутствует, создаётся новое состояние из шести навыков и пяти действий, старый объект \`answered\` остаётся в сохранении.
- Старые статические ответы учитываются только в поле \`legacyAnswers\` как исторический факт; **автоматического начисления освоения нет**, поскольку один прежний вопрос не является эквивалентом двух вариативных проверок.
- Если сериализованная структура \`learning\` повреждена, её поля проходят нормализацию и откатываются к безопасным значениям.

## Границы
Нет серверных аккаунтов, авторизации, облачной синхронизации, уведомлений, календарного spaced repetition, проверки открытого письменного объяснения, автоматической проверки идеальных стратегий и итоговой сертификации. Переход к 12 модулям и 60+ качественным заданиям остаётся частью ROADMAP.

## Тестирование
\`tests/learning.test.mjs\` проверяет детерминированность, 250 вариаций для каждого из шести навыков, правильность структуры вариантов, запрет двойной оценки, освоение и повторение, обработку ошибок, перенос предыдущих ответов и учёт реальных событий.

GitHub Actions выполняет \`npm run check\` до публикации сайта; файл \`core/learning.mjs\` копируется в GitHub Pages рядом с остальными модулями.
