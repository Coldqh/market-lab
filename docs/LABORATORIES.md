# MARKET / LAB 1.5 — лабораторные работы

## Статус и учебная цель
Шесть лабораторных привязаны к шести прежним темам. Они не заменяют банк параметрических задач 1.4, а требуют расчёта по текущему терминалу и/или подтверждённых событий реальной синтетической сессии. Финансовая модель и интерфейс 2010-х не менялись.

| Тема | Лабораторная работа | Условие зачёта |
|---|---|---|
| Фьючерсы | Стоимость одного тика | Численный ответ по размеру тика × множителю выбранного инструмента |
| LONG/SHORT | Полный цикл | Новая LONG-позиция → движение рынка → ручное закрытие **той же** позиции |
| Финансовый результат | Валовой P&L | Численно правильный расчёт текущей открытой позиции по рыночной отметке, без комиссий |
| Маржа | Первоначальное обеспечение | Численный расчёт для выбранного тикета, по моделируемой цене исполнения |
| Экономика | Сценарий ОПЕК+ | Сначала зафиксированный прогноз направления WTI, затем запуск указанного сценария и измерение фактического движения |
| Хедж | Нефтедобытчик | Выбор SHORT и **ручное** открытие короткой позиции по CL |

### Принципы
- Виртуальная торговля **никогда не исполняется по команде лаборатории автоматически**.
- Лаборатория может работать с реальными данными учебной сессии: ценами, количеством, инструментом и ценой входа. Любые сделки остаются с комиссией, маржой и возможными убытками.
- Лаборатория 4 (макрошок) зачтётся даже при неправильном прогнозе: оценивается корректно поставленный эксперимент, а не предсказание результата. Объясняется роль ожиданий и дополнительных факторов.
- Лаборатория 2 не засчитывает принудительное закрытие; требуется ручной выход после хотя бы одного шага рынка.
- Начало новой лабораторной работы изменяет активный практикум, но не удаляет ранее завершённые другие работы.
- Повторный запуск завершённой лаборатории сознательно обнуляет результат **только этой** работы, чтобы можно было повторить опыт.

### Хранение и миграция
Отдельное чистое ядро `core/labs.mjs` хранит записи `{active, records}` и передаёт новые состояния, а не меняет входной объект. При миграции v7 → v8 прежние сессии сохраняются и получают пустой список лабораторных работ. Предшествующие торговые события не засчитываются задним числом. Старые ключи localStorage v4–v7 не удаляются. Повреждённые или неизвестные поля лабораторий нормализуются.

### Ограничения
- Уровни маржи, синтетические новости и исполнение остаются учебными упрощениями.
- Хеджирование в практикуме моделирует лишь фьючерсную сторону сделки, без физической нефти, базисного риска, объёма будущих поставок и реального риска контрагента.
- Нет свободного текстового объяснения, индивидуального исторического Replay и серверной учётной записи.
- Задания используют существующую вёрстку и некоторые вспомогательные встроенные стили полей ввода в палитре терминала; **основные HTML/CSS-файлы неизменны**.

### Автоматическая проверка
`tests/labs.test.mjs` покрывает вычисления по MNQ/CL/GC, реальные данные позиции, расчёт маржи по модели исполнения, последовательность событий, эксперимент с макрошоком, хедж и нормализацию сохранений. `npm run check` запускается перед публикацией GitHub Pages.
